Transaction Lifecycle

From wallet to Finality

Every SIKKA transaction follows a deterministic lifecycle before it is batched into a finalized checkpoint.

Step 01
Build TX
Wallet assembles a transfer — kind, from, to, amount (CHILLAR), nonce, timestamp, and chain id — over the SIKKA/tx/v3 wire format.
Step 02
Spend a Credit
Each account burns 1 spend credit (+1/min, cap 100) to rate-limit spam. No proof-of-work required.
Step 03
Sign (ML-DSA-87)
All signers apply ML-DSA-87 signatures. Multisig: up to 16 parties sign collaboratively.
Step 04
Broadcast
Submitted to any node via HTTP API. Node validates and gossips to peers.
Step 05
Finalize
Transactions are batched into a checkpoint. Once ≥2/3 of the bonded stake votes, it finalizes — the state root is signed and the raw txs are discarded.
Checkpoint finality — cumulative bonded-stake quorum
Consensus

Checkpoint Finality

SIKKA uses bonded-stake checkpoint voting. A round-robin proposer batches transactions, validators vote, and the checkpoint finalizes once ≥2/3 of the active bonded stake agrees. At that point the state root is signed and the transactions are discarded.

If the proposer is slow, automatic 10-second timeout fallbacks keep the chain moving. Downtime never burns stake — only double-signing (equivocation) is slashed.

Non-Punitive Consensus

Validators rotate as proposer on a round-robin schedule with automatic 10-second timeouts. Missing a turn never costs stake; only equivocation — signing two conflicting checkpoints — is slashed. This keeps participation cheap and honest.

Deterministic Finality

Finality is solely a function of bonded stake and checkpoint height — computed with 128-bit fixed-point integer math. Every honest node converges on the identical finalized state root, with no floating-point divergence between CPUs.
