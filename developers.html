Overview

Everything in SIKKA is one POST /api/rpc call to any node on port 64552. The built-in wallet, address lookup, and explorer are all written against this same interface — so the fastest way to learn the protocol is to read them. This guide distills those pages into four reusable building blocks: connect, look up, create keys, and send a transfer. Every example is copy-paste ready.

Methods you'll meet today: chain.info account.get account.proof validator.list tx.submit

1 Connect to a node

Every node speaks JSON-RPC 2.0 over HTTP POST /api/rpc. Point at https://1.sikkalabs.com (mainnet) or your own node. That's the entire setup.

curl — chain.info 
# One call to see the whole network — height, supply, validators
curl -s https://1.sikkalabs.com/api/rpc \
  -H 'content-type: application/json' \
  -d '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"chain.info",
    "params":null
  }'
Sample result
chain_id"sikka-mainnet-v1"
height12938421
total_supply19960907000000000000
total_bonded802113100000000000
active_validators42
peers / mempool7 / 3

You don't need a node to start — 1.sikkalabs.com accepts these calls over HTTPS. Run your own to get the same API on localhost and to serve your own copy of this guide's pages.

2 Look up an account

Addresses are 0x + 64 hex characters (32 bytes), derived from an ML-DSA-87 public key. Fetch a balance with account.get, and cross-check it against the finalized state root with account.proof.

curl — account.get 
curl -s https://1.sikkalabs.com/api/rpc \
  -H 'content-type: application/json' \
  -d '{
    "jsonrpc":"2.0",
    "id":1,
    "method":"account.get",
    "params":{ "address":"0x…" }
  }'
account.get → result
existstrue
balance125000000000
bondnull
battery_now72
nonce / next_nonce3 / 4

Amounts are integers. Balances are in CHILLAR — 10⁹ CHILLAR = 1 SIKKA. Read them as BigInt, never as floats. This is why the wallet uses json-bigint.

Listing validators? validator.list — each entry reports bond, active, and slash / unbonding state.

Verify with a proof

SIKKA discards transaction history, so trust comes from a state root. Request a proof and compare the returned state_root to the finalized checkpoint. The account is either included (has funds) or absent (zero balance that round).

address.html — verify a proof 
const proof = await rpc("account.proof", { address })
// The checkpoint header is flattened onto checkpoints, so state_root
// lives on the checkpoint itself — not checkpoint.header.
const height = proof.checkpoint?.height
const root    = String(proof.state_root || "").toLowerCase()
const committed = String(proof.checkpoint?.state_root || "").toLowerCase()

if (!root || !committed || root !== committed) {
  throw new Error("state_root does not match the checkpoint")
}
const status = proof.account != null
  ? `included · height ${height}`
  : `absent · height ${height}`

3 Create a wallet

Keys are ML-DSA-87 (NIST FIPS 204, Level 5). In the browser we use @noble/post-quantum. Keygen is two lines, and the private key never leaves the page.

wallet.html — keypair + address 
import { ml_dsa87 } from "https://esm.sh/@noble/post-quantum@0.6.1/ml-dsa.js"
import { sha3_256 } from "https://esm.sh/@noble/hashes@2.2.0/sha3.js"
import { randomBytes } from "https://esm.sh/@noble/post-quantum@0.6.1/utils.js"

// 1. seed → keypair (secret 4896 B · public 2592 B)
const { secretKey, publicKey } = ml_dsa87.keygen(randomBytes(32))

// 2. Address = sha3-256(publicKey) as 0x-hex, 32 bytes
const hex = (b) => Array.from(b, x => x.toString(16).padStart(2, "0")).join("")
const address = "0x" + hex(sha3_256(publicKey))

console.log({ address, scheme: "ML-DSA-87" })

Restore from a 32-byte seed, a 4896-byte private key, or a sikka_key.json keystore. Guard the seed — it's the only way back to your funds. Restore verifies that the stored public_key matches the derived key.

4 Sign & send

A transfer is a small signed object sent via tx.submit. Signing binds the transaction to the node's chain_id with ML-DSA-87 context SIKKA-v1. The recipient receives the exact amount — no fee is ever deducted.

Wire format — signingBytes from wallet.html:

# tag "SIKKA/tx/v3" · str(chain_id) · kind · from · to ·
# amount · nonce · timestamp · public_key
# str(x) = u32le(byte_len) + utf8(x); amount/nonce/ts are u64le
JS — sign a transfer (from wallet.html) 
const msg = concat(
  TX_SIGNING_TAG,                 // "SIKKA/tx/v3"
  encodeStr(chainId),             // bind to this network
  Uint8Array.of(0),             // kind = transfer
  from, to,                       // 32 raw bytes each
  u64le(amountChillar),           // amount in CHILLAR
  u64le(nonce), u64le(now),
  publicKey,
)
const signature = ml_dsa87.sign(msg, secretKey, { context: SIGNING_CONTEXT })

const tx = {
  kind: "transfer",
  from: myAddress, to: toAddr,
  amount: amount, nonce, chain_id: chainId,
  public_key: "0x" + toHex(publicKey),
  signature: toHex(signature),
}
curl — tx.submit 
curl -s https://1.sikkalabs.com/api/rpc \
  -H 'content-type: application/json' \
  -d '{
    "jsonrpc":"2.0","id":1,"method":"tx.submit",
    "params":{ "transaction": { …signedTx } }
  }'
# → { "result": { "accepted": true, "id": "…" } }
